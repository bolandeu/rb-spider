[Keep a Changelog](https://keepachangelog.com/), версии следуют
[SemVer](https://semver.org/) (пока версия `0.x`, ломающее изменение поднимает minor).

added/changed/deprecated/removed/fixed/security), а `scripts/release.py` собирает

## [0.3.0] - 2026-10-01

### Added

- Представления `spider_v1_crawls`, `spider_v1_pages`, `spider_v1_issues`, `spider_v1_links` — для Directus и других инструментов; `spider db import-sqlite` — разовый перенос локальной базы в общую.

### Changed

- Общая база PostgreSQL (homeserver): таблицы, индексы и представление ссылок теперь с префиксом `spider_` (`spider_pages`, `spider_links` … — и в `spider query`), у каждой таблицы PRIMARY KEY, таблица версий — `alembic_version_spider`; локальная SQLite переводится сама при первом открытии (миграция 0033 переписывает файл целиком — нужно свободное место размером с базу). PostgreSQL больше не мигрирует при открытии и не получает в `public` своих функций и агрегатов (`sum/max/min(boolean)`, `round`, `group_concat`, `instr`): схему создаёт и обновляет `spider db upgrade`, остальные команды отвечают `DATABASE_NOT_MIGRATED` (выход 1) или `CLI_TOO_OLD` (6). Переменная — `SPIDER_DATABASE_URL`; недоступная база — `DATABASE_UNAVAILABLE` (выход 5, было `REMOTE_DATABASE_UNAVAILABLE`, 1). Функция в `spider query` — `spider_casefold(x)`. Нужен SQLite 3.44+.

### Deprecated

- `SPIDER_DB_URL` → `SPIDER_DATABASE_URL` (старое имя читается с предупреждением, `doctor` показывает `database_env`); `spider db migrate` → `spider db upgrade` (старое имя скрыто и будет убрано).


## [0.2.4] - 2026-09-29

### Added

- `crawl.fingerprint_timezone = ip` (по умолчанию): часовой пояс браузера с отпечатком — как у выходного IP, при старте и после каждой смены IP; `file` — как в файле отпечатка. SOCKS5-адреса в `crawl.proxy_urls` (запасной вход мобильного прокси) работают для страниц; после смены IP соединения старого IP закрываются, а не дают ошибки.
- Мобильный прокси: `crawl.proxy_mode = failover` — всё через первый рабочий адрес, следующий — запасной (HTTP- и SOCKS5-вход модема); `crawl.proxy_change_ip_urls` — ссылки смены IP, которые spider открывает по очереди, когда сайт блокирует (`crawl.proxy_change_ip_on`, по умолчанию 403 и 429), и повторяет заблокированные запросы с новым IP (обход и `spider fetch`). Ключ ссылки — `{key}`, секрет `spider auth login --provider proxy_key` или `SPIDER_PROXY_KEY_API_KEY`.
- Отпечаток браузера `crawl.fingerprint`: файл сервиса отпечатков (`spider fingerprints add`) или сгенерированный browserforge (`spider fingerprints new --os windows|macos|linux|android --chrome N`), один на весь обход — User-Agent, Accept-Language и sec-ch-ua всех запросов, а в браузере рендеринга navigator, экран, WebGL, часовой пояс и локаль; WebRTC только через прокси. Сверка согласованности — одна ОС в отпечатке и у TCP прокси, ОС машины при рендеринге, страна и часовой пояс выходного IP: `spider fingerprints check` и перед обходом (`crawl.fingerprint_check` = warn | stop | off). При смене IP прокси — новые cookies и браузерная сессия с тем же отпечатком.
- Профили для всех проектов: `spider profiles init NAME --user` кладёт профиль в папку настроек пользователя (`~/.config/spider/profiles/` на Linux, `~/Library/Application Support/spider/profiles/` на macOS); `--profile NAME` находит его в любом проекте, проектный профиль с тем же именем важнее.


## [0.2.3] - 2026-09-29

### Added

- Прокси (`crawl.proxy_urls`) несёт весь трафик к сайту: robots.txt, XML sitemap и браузер рендеринга тоже. Прокси проверяется перед обходом и `spider fetch`; мёртвый (не оплачен, неверный пароль) — остановка с кодом 5 `PROXY_UNAVAILABLE` и `spider crawls resume`, либо обход без него: `crawl.proxy_fallback = direct` или ответ «да» в терминале. Посреди обхода прокси считается умершим после `crawl.proxy_max_failures` ошибок подряд; URL, упавшие из-за него, запрашиваются снова. В JSON `crawl` — ключ `proxy_down`.


## [0.2.2] - 2026-09-29

### Fixed

- Страницы в устаревших кодировках (windows-1251, koi8-r и др.) читаются как текст: кодировка берётся из заголовка, `<meta charset>` или угадывается по байтам. Раньше title, текст и HTML таких страниц превращались в «�», а `spider fetch --include markdown` падал с UnicodeDecodeError.


## [0.2.1] - 2026-09-28

### Changed

- Extra `gsc` ставит пакет `rb-google-search-console` (бывший `gsc`, v0.4); `spider doctor` дополнительно показывает внешние программы (`lighthouse`, `npx`) — необязательные, здоровье не портят. Пароли из keychain `rb_spider:<provider>` (до 0.2.0) по-прежнему читаются, но `auth logout` их больше не удаляет.

### Fixed

- В `--help` снова видны квадратные скобки: названия extras (`rb-spider[render]`, `rb-spider[postgres]` …) и разделы конфига (`[custom]`, `[[custom.search]]`) больше не съедаются разметкой.


## [0.2.0] - 2026-09-27

### Changed

- **Ломающее.** `spider auth status` отдаёт общий для наших инструментов отчёт (стандарт §8): `tool`, `version`, `checked_at`, `credentials[]` с `provider`, `required`, `source`, `status` и др. вместо прежних `{provider, authenticated}`; `--check` проверяет секреты (`database` — подключением к `SPIDER_DB_URL`), `--provider` фильтрует; провайдеры `proxy`, `site`, `database` необязательные. Секреты в системном хранилище ключей теперь под именем `spider:<provider>` (как и переменные `SPIDER_*`); сохранённые прежней версией `rb_spider:<provider>` по-прежнему читаются, `auth logout` удаляет оба. Версия берётся из git-тега, changelog собирается из фрагментов (шаблон cli-generator v1.2.3, стандарт выпуска); примеры в `--help` команд — строками `Example:`. Extras `sitemaps` и `gsc` ставят rb-sitemap-xml и gsc из GitHub по тегам (v0.1.1, v0.3.0), а не из соседних каталогов.


## [0.1.0] - 2026-09-27

### Added

- Каркас CLI `spider` (пакет `rb-spider`) по архитектуре `cli-builder`: `doctor`, `init`, `status`, `config list|get|set`, `auth login|logout|status`, `skill install`, `--json`/`--ai`/`--version`, фиксированные коды выхода, секреты в системном хранилище ключей.
- `spider crawl <url>`: обход сайта в ширину (Crawlee + impit, разбор selectolax), каждый ответ — строка в базе, шаги редиректов сохраняются отдельно, `--max-urls` — точная граница, `--concurrency`.
- `spider crawls list`: обходы всех проектов, новые сверху.
- База обходов — одна на пользователя в папке данных приложения (`SPIDER_DB_PATH` переопределяет), схема через миграции Alembic; `spider doctor` показывает её путь.
- Движок SEO-проверок: правила после обхода (SQL или Python), типы и приоритеты как в Screaming Frog; `spider issues` — сводка, `spider urls --issue <код>` — URL проверки, `spider analyze` — пересчёт без переобхода. Первые 9 проверок группы Response Codes: нет ответа, 4xx, 5xx, петли и цепочки редиректов, 3xx, meta refresh, HTTP Refresh, запрет robots.txt.
- Обход соблюдает robots.txt (запрещённые URL попадают в отчёт), записывает URL без ответа и цели meta / HTTP Refresh.
- Настройки обхода слоями (встроенные → глобальный → проект → профиль → `--config` → `SPIDER_<РАЗДЕЛ>__<КЛЮЧ>` → флаги → `--set`), любой ключ меняется через `--set`; `spider config show` — итог и слой каждого значения, `config validate`, `config schema` (JSON Schema), `config get/set` понимают ключи настроек.
- Профили: встроенные `default`, `googlebot`, `yandexbot`, `fast`, свои в `.spider/profiles/` с наследованием `extends`; `spider profiles list|show|init`. Ключ `crawl.user_agent`.
- `spider crawls show` — обход и снимок настроек, с которыми он шёл. `docs/profiles.md` — слои, формат профиля и таблица ключей, сгенерированная из схемы.
- `spider redirects [--only all|chains|errors]` — отчёт по редиректам: каждый шаг (3xx / meta / HTTP Refresh) до конечного URL и кода. Порог цепочки `thresholds.redirect_chain_hops`; `spider analyze` берёт пороги из текущих настроек (`--profile`, `--set`).
- 24 on-page проверки: Page Titles, Meta Description, H1, H2 (нет, несколько, вне `<head>`, дубли, длина, alt в H1, порядок заголовков, title = H1). Пороги длины — раздел `thresholds`. Дубли ищутся одним проходом (оконная функция SQL), без сравнения каждой страницы с каждой.
- Сбой соединения больше не печатает трассировку Crawlee: такие URL и так попадают в отчёт (`internal_no_response`).
- 19 проверок директив и canonical: noindex / nofollow / none / nosnippet / noimageindex / unavailable_after / notranslate / устаревшие noodp и noydir (meta robots и X-Robots-Tag), meta robots вне `<head>`; canonical — нет, несколько, конфликт, вне `<head>`, лишние атрибуты, фрагмент, относительный, склейка с другим URL, ведёт на неиндексируемый URL (canonical из HTML и заголовка Link).
- Индексируемость каждого URL и причина (как Indexability Status в Screaming Frog); проверки дублей учитывают только индексируемые страницы. Цели canonical тоже обходятся.
- Проверки контента: точные дубли (md5 HTML), «Lorem ipsum», мало текста (`thresholds.low_content_words`, 200 слов видимого текста).
- `--store-html` (`crawl.store_html`): HTML страниц сжимается zstd и хранится в `spider-html.sqlite` рядом с базой; по умолчанию — только md5.
- Настройки обхода: `max_depth`, `max_links_per_page`, `max_url_length`, `include` / `exclude` (регулярные выражения), `all_subdomains`, `stay_in_start_folder`, `max_rps`, `timeout_s`, `headers`, `content_exclude` (по умолчанию текст меню и подвала не считается), пресеты `user_agent` (googlebot, googlebot-smartphone, bingbot, yandexbot, chrome), прокси с чередованием и паролем из системного хранилища ключей; флаги `--max-depth`, `--user-agent`, `--ignore-robots`.
- robots.txt читается от имени User-Agent обхода (или `robots_user_agent`), режимы `respect` / `ignore` / `report`, соблюдается Crawl-delay.
- `spider doctor` проверяет настройки и только те секреты, которые они требуют (пароль прокси).

- Ссылки: граф ссылок (анкор, alt картинки-ссылки, rel, nofollow, тип — ссылка, canonical, редирект, refresh), `spider links <url> --in|--out`. Внешние ссылки и URL за пределами стартовой папки проверяются (код ответа), но не обходятся. Раздел `collect.*` (follow / store для внутренних и внешних ссылок, canonical, refresh), `crawl.follow_internal_nofollow`, `crawl.follow_external_nofollow`, `crawl.check_outside_start_folder`.
- 16 проверок: 12 группы Links (ссылки на localhost, «нерабочие» ссылки, тупики, входящие только с неиндексируемых / только nofollow / и те и другие, много исходящих, глубина, без анкора, неинформативный анкор), внешние нет ответа / 4xx / 5xx, Canonicals: Unlinked. Пороги `thresholds.crawl_depth`, `internal_outlinks`, `external_outlinks`, `non_descriptive_anchors`.
- Проверки, чьи данные не собирались (`collect.*` выключен), не считаются пройденными: `spider issues` перечисляет их в `not_checked`.
- Ресурсы страниц: картинки (и `srcset` по `collect.images_srcset`), CSS, JS, видео и аудио, iframe — проверяются (код ответа, вес) по `collect.images|css|js|media|iframes`, хранятся строками ссылок своего типа. robots.txt применяется ко всем скачиваемым URL, в том числе ресурсам и чужим сайтам.
- 7 проверок: картинки без alt / с пустым alt / с длинным alt / тяжелее `thresholds.image_kb` / без width и height (по URL картинки); Internal и External Blocked Resource.
- Большие обходы: очередь в памяти + таблица `frontier` в базе (отметка «обработан» пишется одной транзакцией со страницей), запись раз в 500 страниц или 2 с. `spider crawls resume` продолжает обход после Ctrl-C, падения или `kill -9` без потерь и повторных скачиваний; `spider crawl --detach` — обход в фоне (лог рядом с базой); `spider status` — прогресс (сохранено, в очереди, жив ли процесс), проект не нужен.
- Режим списка: `spider crawl --list urls.txt` (или `--list -` из stdin, ключ `crawl.mode = list`) — аудит заданных URL без перехода по ссылкам, редиректы (3xx, meta и HTTP Refresh) проходятся до конца; «свой сайт» для проверок — хосты из списка. Результат — обычный обход: все команды анализа, `--detach` и `crawls resume` работают.
- Управление данными: `spider crawls delete <id>…`, `spider crawls prune --keep-last N | --older-than 90d` (по проектам, `--project-name`), `spider projects list | delete`, `spider db info | migrate | vacuum`. Удаление спрашивает подтверждение, `--yes` (`-y`, `--confirm`) — без вопроса, `--dry-run` — показать, что удалится; идущий обход не удаляется.
- `spider url <url>` — всё о странице: ответ, on-page данные, индексируемость и причина, проблемы, число входящих и исходящих ссылок, ресурсы (картинки, CSS, JS) с кодом, весом и alt.
- `spider export [pages|links|issues] --format csv|json [-o файл]` — потоковая выгрузка (память не растёт) с фильтрами `--issue`, `--status 404|4xx` (у URL или цели ссылки), `--external`: все URL, все ссылки и анкоры, внешние ссылки, ссылки на URL с данным кодом, все находки проверок.
- `spider query "SELECT …"` — свой SQL только на чтение: база открывается read-only, SQLite отклоняет всё, кроме SELECT; `--format csv|json` — все строки потоком.
- JS-рендеринг: `spider crawl --render always` (`crawl.render`) — HTML-страницы с кодом 200 ещё и открываются в браузере (Playwright через Crawlee, extra `rb-spider[render]`), SEO-данные берутся из DOM после выполнения скриптов; коды, редиректы и ресурсы проверяются как обычно. `crawl.render_tabs` — вкладок одновременно, `crawl.render_wait_ms` — ожидание скриптов после загрузки, `pages.rendered` — данные из DOM или (сбой рендера) из сырого HTML. Браузер находится сам: сборка Playwright, иначе самая свежая сборка Chromium из кэша Playwright (другие версии Playwright оставляют их там), иначе установленный Google Chrome; свой путь — `crawl.render_browser`. Без Playwright или браузера — ошибка `RENDER_UNAVAILABLE` с подсказкой до начала обхода.
- Обогатители: плагины через entry points `rb_spider.enrichers` добавляют метрики к URL обхода (таблица `url_metrics`); `spider enrichers` — установленные плагины (сломанные — с причиной), `spider enrich [crawl_id] [--plugin]` — запуск, метрики видны в `spider url`. Сбой плагина — код 5 с его именем, прежние метрики остаются.
- Рецепты — встроенные профили `quick-audit`, `migration`, `js-site`, `broken-links`, `big-shop`; в `docs/profiles.md` — таблица «задача → профиль → что смотреть после», пример профиля с прокси и сгенерированный список встроенных профилей (каждый блок проверяется `spider config validate`). Профиль в режиме списка с одним URL (`--profile migration <url>`) — список из одного URL.
- Скилл для агентов (`spider --ai`, `spider skill install`): как выбрать и составить профиль и в каком порядке звать команды анализа (drill-down).
- `spider fetch <url>… | --list file|-` и публичный Python API `rb_spider.fetch` (`fetch`, `fetch_many`, `fetch_stream`) — общий сборщик страниц для других инструментов, без обхода и без базы: финальный URL, код, шаги редиректов, время, SEO-данные; `--include headers,links,resources,text,markdown,html`; прокси, User-Agent и профили — из настроек обхода; `--render` — через браузер. `--markdown` — страница Markdown-документом для LLM: свой конвертер на selectolax, основной контент без меню, подвала и сайдбаров, ссылки абсолютные, таблицы, списки, код.
- У каждого URL хранятся время ответа (`response_ms`), заголовки ответа и Last-Modified; `spider url` показывает их и заголовки запроса обхода. `crawl.max_redirects` (по умолчанию 20) — сколько шагов одной цепочки редиректов проходить.
- `spider overview` — сводка обхода (как Crawl Overview): найдено / заблокировано / не ответило / индексируется, типы содержимого сайта и чужих URL, коды ответа, индексируемость с причинами, canonical (нет / на себя / на другой URL), директивы, глубина.
- Колонки ссылок у каждой страницы: `inlinks`, `unique_inlinks`, `unique_outlinks` (считаются в `analyze` одним проходом); `spider export pages --type html|js|css|image|pdf|other|unknown` и колонка `content_kind`; в `spider issues` — доля URL сайта (`percent`).
- `crawl.http_client = "curl"` — запасной HTTP-клиент (curl-impersonate, extra `rb-spider[curl]`) для обхода и `spider fetch`; без extra — ошибка `HTTP_CLIENT_UNAVAILABLE` до начала обхода.
- Справка всех команд на русском с примерами и формой `--json`; тесты: у каждой команды есть docstring, у каждой опции `help=`, снимки `--help` каждой команды.
- 11 проверок группы URL: несколько слешей подряд, пробел, битый якорь (`#id`, которого нет на целевой странице), символы вне ASCII, заглавные буквы, повтор сегмента пути, внутренний поиск (`thresholds.internal_search`), GET-параметры, метки аналитики (`utm_*`, `_ga`, `_gl`), подчёркивания, длина больше `thresholds.url_max_chars` (115). Признаки адреса считаются в `analyze` одним проходом пачками (`pages.url_issues`); якоря страницы хранятся 2-байтовыми отпечатками (`pages.anchor_ids`), фрагмент ссылки — в `links.fragment`.
- Переписывание найденных URL, раздел `[rewrite]`: `remove_params` (удалить параметры), `regex` (замены по порядку), `lowercase`, `percent_encoding` (`keep` / `upper` / `lower`). Действует на ссылки, ресурсы, редиректы, refresh и canonical; стартовый URL и URL списка не меняются.
- Hreflang: аннотации из `<link rel="alternate" hreflang>` и заголовка Link (`collect.hreflang.follow` / `.store`), 12 проверок — цель не 200, нет обратной ссылки, обратная ссылка с чужим кодом, на неканонический URL, на noindex, неверные коды ISO 639-1 / ISO 3166-1, повтор кода, не указан свой canonical, вне `<head>`, URL только из hreflang, нет ссылки на себя, нет x-default. `spider hreflang [--only …]` — отчёт по аннотациям (как Reports → Hreflang), `spider overview` — страницы с hreflang и без.
- Пагинация rel next/prev (`<link>` и заголовок Link, `collect.pagination.follow` / `.store`): 7 проверок — URL не стоит ссылкой `<a>`, цель не 200, на цель нет ссылок, несколько next/prev, петля, несходящиеся пары, неиндексируемая страница серии; `spider pagination [--only all|non_200|unlinked]` — отчёт, `spider overview` — страницы в сериях (первые и 2+). `thresholds.ignore_paginated_duplicates` (по умолчанию включён): страницы 2+ не считаются дублями по title, description, H1, H2.
- Безопасность: 12 проверок — URL по HTTP, смешанное содержимое, форма на HTTP-адрес и на HTTP-странице, нет HSTS, CSP, X-Content-Type-Options, X-Frame-Options, безопасного Referrer-Policy, `target="_blank"` без `noopener`, протокол-относительные ресурсы, содержимое не совпадает с Content-Type (по сигнатуре файла). `spider insecure` — отчёт Insecure Content, `spider overview` — URL сайта по https / http, `spider export pages --scheme http|https`. `crawl.respect_hsts` — http-ссылки хоста с HSTS записываются как 307 «HSTS Policy» без запроса (как в браузере), `crawl.verify_tls = false` — обход сайтов с самоподписанным сертификатом.
- Контент: soft 404 (title / H1 по шаблонам `thresholds.soft_404_patterns`), читаемость — индекс Флеша (для русского текста формула Оборневой) и две проверки по порогам `readability_difficult` / `readability_very_difficult`, доля текста в HTML (`text_ratio`). Почти-дубли: `collect.near_duplicates` (extra `rb-spider[near]`, datasketch) хранит подпись MinHash текста, `analyze` ищет пары полосами LSH в SQL с порогом `thresholds.near_duplicate_similarity` (90 %), память не растёт. `spider duplicates [--kind exact|near] [--url … --diff]` — пары дублей с процентом сходства и разницей текста.
- Микроразметка: `collect.structured_data` (`json-ld`, `microdata`, `rdfa`; по умолчанию выключено) — JSON-LD разбирается сам, Microdata и RDFa через extruct (extra `rb-spider[structured]`); проверка по словарю Schema.org (таблица `data/schemaorg.json` из официального релиза, `scripts/build_schemaorg.py`) и по обязательным и рекомендуемым свойствам основных функций расширенных результатов Google. 6 проверок (ошибки и предупреждения Schema.org и Google, ошибки разбора, нет разметки); `spider structured [--report validation|features]` — сводки, `spider url` — сообщения страницы и сама разметка (при `--store-html`), `spider overview` — страницы с разметкой по форматам.
- XML sitemap через соседний пакет rb-sitemap-xml (extra `rb-spider[sitemaps]`): `sitemaps.crawl` читает sitemap в начале обхода (robots.txt и стандартные пути — `sitemaps.discover`, свои — `sitemaps.urls`), его URL обходятся (`sitemaps.follow`), hreflang из `xhtml:link` идёт в проверки Hreflang. 6 проверок — больше `thresholds.sitemap_max_urls` URL или `sitemap_max_mb` МБ в файле, индексируемая страница не в sitemap, «сироты», неиндексируемые в sitemap, URL в нескольких sitemap. `spider sitemaps show [--only files|urls|orphans|not_in_sitemap]`, `spider sitemaps build` — XML / Image Sitemap по обходу (разбиение по 49 999 URL, индекс, lastmod, changefreq, priority), `spider overview` — сводка. `spider crawl --list` и `spider fetch --list` принимают XML sitemap и CSV с колонкой url / address / loc. Установка с пакетом: `uv tool install --with-editable <путь к sitemap-xml> "rb-spider @ git+…"`.
- Ширина в выдаче Google: title и description в пикселях (Arial 20px / 14px — `thresholds.serp_*_font_px`; таблица ширин `data/arial_widths.json`, `scripts/build_font_widths.py`), 4 проверки по порогам `title_min_px` / `title_max_px` (200 / 561) и `description_min_px` / `description_max_px` (400 / 985). Сниппет с обрезкой по словам — в `spider url`; `spider serp summary` — SERP Summary, `spider serp preview` — предпросмотр для своего текста без обхода.
- Валидность HTML (9 проверок) по исходному коду, который HTML5-парсер иначе молча исправляет: нет / несколько `<head>` и `<body>`, элементы до `<html>`, `<head>` не первый, недопустимый элемент в `<head>` (Google заканчивает head на нём), HTML больше `thresholds.document_max_mb` и JS / CSS больше `resource_max_mb` (2 МБ). Мобильная версия: нет viewport с `width=`, плагины Flash / Silverlight / Java, `<link rel="alternate" media>` на мобильный сайт (`collect.mobile_alternate`). Выключатель проверки исходника — `collect.html_validation`.
- Настройки обхода (#35): лимиты `crawl.max_page_size_kb`, `max_urls_per_depth`, `max_folder_depth`, `max_query_params`, `max_urls_per_subdomain`, `path_limits`; `retries_5xx`; `cookies` (`session` — одно хранилище на весь обход, `none`); `assume_html`; `keep_fragments`; `crawl_invalid_links` (по умолчанию ссылки без хоста теперь отбрасываются); `list_follow_canonicals`; `cdns`; `robots_custom`, `robots_show_internal_blocked` / `robots_show_external_blocked` и совпавшая строка robots.txt у заблокированных (`pages.blocked_rule`); Basic-авторизация сайта (`crawl.auth`, пароль — `spider auth login --provider site`, к чужим сайтам не уходит); `ca_bundle` — свой корневой сертификат (клиент curl); `collect.uncrawlable_links`; пороги `thresholds.issues_indexable_only`, `self_refresh_non_indexable`.
- Custom Search и Custom Extraction (раздел `[custom]`): `[[custom.search]]` — сколько раз текст или регулярное выражение встречается в HTML, тексте или элементах по CSS; `[[custom.extract]]` — значения по CSS, регулярному выражению или XPath (extra `rb-spider[xpath]`, lxml): текст, HTML, inner HTML или атрибут. Результаты — таблица `custom_values`, `spider custom [--search|--extract NAME] [--without]`. Зона каждой ссылки (nav, header, footer, sidebar, content — `custom.link_positions`) и, с `collect.link_path`, путь её предков — в `spider links`.
- `spider compare <старый> <новый>`: новые и пропавшие URL, по каждой проверке added / new / removed / missing (как Compare mode Screaming Frog), Change Detection по полям `compare.fields` (индексируемость, код, title, description, H1, H2, canonical, директивы, слова, контент, глубина, ссылки, типы разметки); списки — `--issue КОД --status …`, `--field ПОЛЕ`, `--urls new|missing`. `spider crawls respider <id> <url>… | --list` — переобойти выбранные URL обхода и пересчитать проверки. `spider --verbose analyze` / `crawl` пишет время каждой проверки.
- Выгрузки и отчёты (#38): `--format xlsx` (потоком, openpyxl), `spider export --preset audit|links|full -o папка|файл.xlsx` (пресеты — `export.presets`), наборы `queued`, `headers`, `cookies`, `source`, `text` (с `--store-html`), `duplicates`, `custom`, `sitemap-urls`; `spider export links --issue КОД` — ссылки, из-за которых сработала проверка; тип пути ссылки (`path_type`). Группа `spider report`: `canonicals` (Canonical Chains, Non-Indexable Canonicals), `structure`, `response-times`, `crawl-path`, `meta-keywords`, `forms`, `headers [--cookies]`; `spider redirects --canonicals` (Redirect & Canonical Chains); `spider robots-test` — проверка URL по robots.txt сайта или своему файлу. `--list` принимает Excel (.xlsx).
- JavaScript (#39): при рендеринге исходный HTML разбирается рядом с DOM — колонки `raw_title`, `raw_meta_description`, `raw_h1`, `raw_canonical`, `raw_directives`, `raw_word_count` и происхождение каждой ссылки (`links.origin`: html / rendered / html & rendered, Link Origin). 16 проверок группы JavaScript: noindex / nofollow только в исходном HTML, canonical разный или только после JS, title / description / H1 добавлены или изменены скриптом, ссылки и текст из JS (`thresholds.js_content_min_words`), ошибки консоли, ресурсы, закрытые robots.txt (браузер их не грузит, как Googlebot), старая схема AJAX (`#!`, `_escaped_fragment_`, `<meta name="fragment">` — без рендеринга); Internal Redirection (JavaScript) — уход скриптом на другой URL записывается как редирект (`refresh_kind = javascript`), цель обходится. `crawl.render = "auto"` — рендерит первые `render_auto_sample` страниц и продолжает, только если JS что-то меняет; `render_viewport` (desktop / mobile / ШxВ), `render_console`, `render_flatten_shadow_dom`, `render_flatten_iframes`. `spider report javascript` — Chrome Console Log Summary и незагруженные ресурсы, `spider export javascript` — построчно. Проверки, которым нужен рендеринг, в обходе без него — «не проверялось» (`requires`: `crawl.render!=never`).
- Картинки (#40): реальный размер каждой картинки из заголовка файла (`imagesize`, `pages.image_width` / `image_height`), с рендерингом и `crawl.render_images` — ещё и размер, в котором её показывает страница (таблица `rendered_images`); оба — в `spider url` (Image Details). ### Changed

- Дубли (точные, title, description, H1, H2) ищутся только среди индексируемых страниц — `thresholds.duplicates_indexable_only`, как в Screaming Frog; раньше точные дубли искались и среди неиндексируемых (например, копия с canonical на оригинал).
- Ссылки хранятся по числовым id URL (таблицы `urls` и `link_rows`, миграция переносит старые обходы): база на 100k страниц — 400 МБ вместо 799, обход ~1935 URL/с вместо ~1500, проверки ~34 с вместо ~38. `links` осталось представлением с прежними колонками — `spider query` и свои запросы работают как раньше.
- Большой обход вдвое быстрее и в 2 раза легче по памяти: бенч 100k страниц при 50 параллельных — ~1500 URL/с и ~325 МБ на все процессы (было 653 URL/с и 597 МБ). Разбор HTML и выбор ссылок идут в отдельных процессах (`crawl.parse_workers`, по умолчанию по числу ядер, не больше 4; маленькие обходы — в одном процессе), очередь не держит в памяти обработанные запросы, запись в базу — в отдельном потоке одним SQL-оператором на пачку, находки проверок не копятся в памяти.
- Ключ `crawl.respect_robots` заменён на `crawl.robots` (`respect` / `ignore` / `report`).

### Fixed

- Запись ссылок могла идти минутами, если в базе уже были небольшие обходы: SQLite по их статистике выбирал перебор таблицы `urls` на каждую ссылку (обход 200 страниц после двух крошечных — 21 с вместо 0,2). id URL теперь подставляются поиском по уникальному индексу.

- Заблокированные robots.txt чужие URL записывались как URL сайта (не заполнялся признак `external`).

- `spider overview`: `totals.indexable` считал и чужие URL, ответившие 200; теперь — только URL сайта, как раздел `indexability`.

- Обход в статусе «идёт» без записанного процесса (зависший, из старой версии) можно удалить: раньше `crawls delete` и `projects delete` считали его идущим.

- Тесты больше не пишут обходы полигона в настоящую базу пользователя (общие фикстуры модулей создавались раньше подмены `SPIDER_DB_PATH`).
